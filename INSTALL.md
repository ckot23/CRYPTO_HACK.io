# Установка и запуск CRYPTO_HACK (Unity)

Игра — симулятор хакера на русском языке: 8 миссий на Python, майнинг-ферма,
биржа с живым графиком, чёрный рынок апгрейдов, школа Python, файлы и профиль
с достижениями. Весь интерфейс собран из C#-кода (uGUI), префабы и сцены
настраивать не нужно.

Гайд рассчитан на человека, который Unity раньше не открывал. Читай по порядку —
до первого запуска примерно 20–30 минут (в основном скачивание редактора).

---

## 1. Что нужно установить

| Что | Зачем | Где взять |
|---|---|---|
| **Unity Hub** | менеджер проектов и версий Unity | <https://unity.com/download> |
| **Unity Editor 6.6** (6000.6.x) — или 2022.3 LTS | сам движок | ставится из Unity Hub, вкладка *Installs* |
| **python3** (необязательно) | режим «настоящий Python»: код из редактора реально выполняется | <https://www.python.org/downloads/> |

Про версию Unity: проект помечен как **Unity 6.6 (6000.6.x)** — это основная
цель. Он открывается и на других версиях: **2022.3 LTS**, Unity 6.0–6.5.
Код не использует новых API, поэтому выбор не критичен — «лишь бы открывалось».
От версии зависит только номер пакета uGUI в `Packages/manifest.json`
(для 6.6 это `2.6.0`, для 2022.3 — `1.0.0`); если редактор пожалуется на пакет —
раздел 8 внизу.

При установке редактора через Unity Hub:
1. *Installs* → **Install Editor** → выбери **Unity 6.6** (в списке он может
   называться `6000.6.x`); справа в выпадающем меню патчей бери последний,
   например `6000.6.2f1`;
2. если 6.6 в списке нет — нажми *Install Editor → Archive* и найди её там,
   либо поставь 2022.3 LTS: проект открывается и в ней;
3. в списке модулей ничего лишнего отмечать не нужно (для Windows-сборки
   достаточно самого редактора; по желанию добавь *Windows Build Support*);
4. жми *Install* и дождись окончания (несколько ГБ).

Без python3 игра тоже работает — просто вместо реального выполнения кода
включается встроенный симулятор Python (см. раздел 6).

## 2. Как получить проект

Любой из трёх способов — результат одинаковый.

**Способ A. Готовый архив (самый простой).**
1. Скачай `CRYPTO_HACK_unity.zip` из корня репозитория.
2. Распакуй в удобную папку **без русских букв и пробелов** в пути, например
   `C:\Games\CRYPTO_HACK_unity` или `~/games/CRYPTO_HACK_unity`.
   Внутри должны оказаться папки `Assets`, `Packages`, `ProjectSettings`
   и файлы `README.md`, `INSTALL.md`.

**Способ B. Через Git.**
```bash
git clone https://github.com/ckot23/CRYPTO_HACK.io.git CRYPTO_HACK_unity
cd CRYPTO_HACK_unity
```

**Способ C. Кнопкой на GitHub.**
Кнопка **Code → Download ZIP**, затем распаковать (как в способе A).

> Важно: именно **папка с `Assets` и `ProjectSettings`** и есть проект Unity.
> Не открывай в Unity папку на уровень выше и не заходи внутрь `Assets`.

## 3. Открыть проект в Unity

1. Запусти **Unity Hub** → вкладка **Projects**.
2. Нажми **Add** (или *Open* в старых версиях) → **Add project from disk**.
3. Выбери папку `CRYPTO_HACK_unity` (ту самую, где `Assets` и `ProjectSettings`).
4. В списке проектов появится `CRYPTO_HACK_unity`. Рядом будет пометка версии
   проекта — `6000.6.2f1` (Unity 6.6), это нормально: это версия, в которой
   проект собирали.
5. Если у тебя другая сборка 6.6 (например `6000.6.0f1`) или другая версия
   Unity: клик по выпадающему списку версии у проекта → выбери ту, что стоит
   у тебя (список установленных — во вкладке *Installs*). Unity покажет диалог
   про смену версии проекта — подтверждай, проект совместим и с 6.6.x, и с
   2022.3 LTS. Если хочешь убрать предупреждение насовсем, впиши свою версию
   в `ProjectSettings/ProjectVersion.txt` — это обычный текстовый файл.
6. Нажми на проект → **Open**.

**Первый запуск долгий**: Unity импортирует ассеты и создаёт папку `Library`
(2–10 минут, зависит от диска). Пока в правом нижнем углу крутится полоска —
ничего не трогай. Окно может мигнуть «Compiling…» — это компиляция скриптов.

Что Unity может спросить при первом открытии:
* доустановка пакетов (**Unity UI**, **Input System**) — соглашайся, они нужны;
* «включить новые бэкенды ввода и перезапустить редактор?» — можно ответить
  как угодно: игра умеет работать и с новым Input System, и со старым Input
  Manager (путь выбирается автоматически, см. раздел 8).

Когда редактор открылся, проверь окно **Console** (Ctrl+Shift+C):
должно быть пусто или только обычные сообщения Unity. Красных ошибок быть не
должно; если они есть — смотри раздел 8.

## 4. Запуск игры

1. В редакторе нажми **▶ Play** (вверху по центру).
2. Появится неоновый экран с «матричным дождём»: `CRYPTO_HACK`.
3. Жми **НАЧАТЬ ИГРУ** → пойдёт «загрузка BIOS» (её можно пропустить
   пробелом) → откроется рабочий стол NeonOS.

**Сцена для запуска не нужна.** Игра стартует сама: при выходе в Play проект
сам создаёт нужные объекты (`RuntimeInitializeOnLoadMethod` в
`Assets/Scripts/GameBoot.cs`). Поэтому:

* если видишь пустую сцену с надписью *Untitled* — это правильно,
  просто жми **▶ Play**;
* сохранять/создавать сцену не надо, но если хочешь — сделай это через
  пункт меню **CRYPTO_HACK → Создать сцену и добавить в сборку** (см. раздел 7).

Остановить игру — снова **▶ Play** (кнопка станет активной во время игры).

## 5. Управление

| Действие | Как |
|---|---|
| Открыть программу | клик по иконке слева (⌁ хак-терминал, ⚙ майнеры, ▲ биржа, ✚ апгрейды, ✎ школа, ▶ файлы, ★ профиль) |
| Горячие клавиши программ | **1 … 7** |
| Свернуть/закрыть окно | кнопка **✗** в шапке окна или кнопка на панели задач; **Esc** закрывает верхнее окно |
| Перетащить окно | тянуть за шапку окна |
| Меню системы | **⌁ GHOST** в левом нижнем углу (звук, обучение, сброс прогресса, выход в главное меню) |
| Запустить код в терминале | кнопка **▶ ЗАПУСТИТЬ** или **Ctrl+Enter** |
| Отступ в редакторе кода | **Tab**; переключение режима — кнопка **РЕЖИМ: PYTHON / СИМУЛЯТОР** |
| Пропустить загрузку BIOS | **пробел** или любая клавиша |
| Сделка на бирже | ввести сумму и жать **ПРОДАТЬ / КУПИТЬ**; **Enter** в поле — подставить максимум |

Редактор кода — свой, с подсветкой синтаксиса и кареткой: кликай по строке,
печатай текст, Backspace/Delete/стрелки/Home/End работают как в обычном
редакторе. Строка состояния снизу справа подсказывает ошибки синтаксиса.

Про ввод: игра не использует `EventSystem`, `Button` и `InputField` — клики
разбирает свой роутер (`Assets/Scripts/UI/Ui.cs`), а мышь/клавиатуру читает
`Assets/Scripts/UI/UiInput.cs`, который сам выбирает доступный стек ввода
(новый Input System или старый Input Manager). Поэтому в настройках проекта
**Active Input Handling** может стоять любой вариант, а менять «модули ввода»
на сцене не нужно вовсе — сцены с объектами в игре нет.

## 6. Настоящий Python или симулятор

В шапке хак-терминала есть кнопка режима, а сверху на рабочем столе — индикатор
`PY: …`.

* **PYTHON** — код запускается настоящим `python3` в отдельном процессе
  (`Assets/Scripts/Core/PyRunner.cs`). Игра подкладывает в скрипт заглушки
  функций `scan()`, `connect()`, `brute()`, `bypass()`, `decrypt()`,
  `extract()`, `drain()`, `install_miner()`, `wallets()` — они печатают
  результат в терминал. Ограничение по времени 8 секунд, вывод построчный.
* **СИМУЛЯТОР** — тот же сценарий, но целиком внутри игры
  (`Assets/Scripts/Core/PySim.cs`): проверяются обязательные конструкции миссии,
  печатается правдоподобный лог, считается стиль кода.

Если Python не найден — кнопка режима гаснет и включается симулятор. Чтобы
включить реальный Python:
* **Windows**: поставь Python с <https://python.org> и галочкой *Add python.exe
  to PATH*; проверь в `cmd`: `py -3 --version` или `python --version`;
* **Linux**: `sudo apt install python3` (обычно уже стоит);
* **macOS**: `brew install python3` или официальный установщик.

Игра ищет по очереди `py -3`, `python`, `python3` (Windows) и `python3`,
`python` (Linux/macOS). Свой пробный запуск она делает при старте, так что
индикатор режима появляется сразу.

## 7. Собрать свою сборку (exe/AppImage и т.п.)

Игра стартует без сцены, но **сборке сцена нужна**. Делается двумя шагами:

1. В Unity: меню **CRYPTO_HACK → Создать сцену и добавить в сборку**.
   Скрипт создаст `Assets/Scenes/Game.unity` и добавит её в *Build Settings*.
2. **File → Build Profiles** (в Unity 6.6 меню называется так; в 2022.3 —
   *File → Build Settings…*): выбери платформу (Windows/macOS/Linux), при
   необходимости **Switch Platform**, затем **Build** и укажи пустую папку
   (например, `Build`).

Готовый билд запускается как обычная программа. Учти: путь к сохранениям у
билда и у редактора общий (см. ниже).

## 8. Если что-то не работает

**В консоли: `The type or namespace name 'UI' does not exist in the namespace
'UnityEngine'`**
Не установлен пакет Unity UI. Открой **Window → Package Manager → Unity
Registry**, найди **Unity UI** (`com.unity.ugui`) → **Install**. Либо поправь
`Packages/manifest.json` руками и перезапусти Unity: номер пакета совпадает с
минорной версией редактора.

| Твоя версия Unity | Строка в `manifest.json` |
|---|---|
| Unity 6.6 (`6000.6`) | `"com.unity.ugui": "2.6.0"` |
| Unity 6.3 (`6000.3`) | `"com.unity.ugui": "2.3.0"` |
| Unity 6.0 (`6000.0`) | `"com.unity.ugui": "2.0.0"` |
| Unity 2022.3 LTS | `"com.unity.ugui": "1.0.0"` |

**Package Manager пишет: `Package [com.unity.ugui@…] cannot be found` /
`cannot be resolved`**
Значит, в манифесте номер пакета от другой версии Unity. Два способа починить:
меню **Help → Reset Packages to defaults** (Unity сама пропишет верные номера)
или таблица чуть выше. После правки `Packages/manifest.json` перезапусти Unity.

**Клики и клавиатура не реагируют, в консоли `InvalidOperationException:
You are trying to read Input using the UnityEngine.Input class…`**
В Player Settings выбрана схема ввода, которой нет в проекте. Зайди в
**Edit → Project Settings → Player → Other Settings → Active Input Handling** и
поставь **Input Manager (Old)** или **Both**, затем перезапусти Unity. Игра
показывает это же предупреждение тостом в углу экрана при старте, так что
искать причину долго не придётся.

**Консоль: `The type or namespace name 'InputSystem' ... does not exist`**
Не установлен пакет **Input System** (`com.unity.inputsystem`). Window →
Package Manager → Unity Registry → **Input System** → Install. Либо удали
строку `"com.unity.inputsystem"` из `Packages/manifest.json` и выставь Active
Input Handling = *Input Manager (Old)*.

**Кнопка Play серая / ничего не происходит**
Идёт компиляция скриптов или импорт ассетов — посмотри полоску прогресса
в правом нижнем углу. Дождись окончания.

**Unity говорит, что версия проекта другая (`6000.6.2f1`)**
Проект помечен как Unity 6.6. Если у тебя другая сборка 6.6 или 2022.3 LTS —
просто соглашайся открыть своей версией: код совместим, изменений в API нет.
Убрать предупреждение совсем можно, вписав свою версию в
`ProjectSettings/ProjectVersion.txt` (версию смотри в Unity Hub → *Installs*).

**Пустая сцена и ничего не появляется после Play**
Значит, не сработал автозапуск. Проверь, что в проекте действительно есть
`Assets/Scripts/GameBoot.cs` (в нём `[RuntimeInitializeOnLoadMethod]`), и что
в консоли нет ошибок компиляции. Как запасной вариант: создай объект вручную
(правый клик в *Hierarchy* → *Create Empty*), добавь ему компонент `GameBoot`
и нажми Play.

**Нет звука**
Звук в игре синтезируется кодом (никаких аудиофайлов). Если тишина:
проверь, что в игре не выключен звук (**⌁ GHOST → Звук: ВКЛ**), и что в
Windows не выбрано другое устройство вывода. При запуске на пустой сцене игра
сама добавляет `AudioListener`.

**Кракозябры вместо букв (кириллица)**
Шрифты лежат в `Assets/Resources/Fonts` (`DejaVuSansMono.ttf`,
`DejaVuSansMono-Bold.ttf`, `JetBrainsMono-LatinExt.ttf`). Если ты их случайно
удалил — положи на место файлы с теми же именами. Символ ₿ есть только в
JetBrains, поэтому его нельзя заменять на шрифт без него.

**Кнопка РЕЖИМ не переключается**
Значит, `python3` не найден — игра работает в режиме симулятора. Это не ошибка,
см. раздел 6.

**Режим PYTHON выбран, но в консоли `Ошибка: python не найден`**
Python установлен, но не в PATH, либо запускается из-под другого пользователя.
Проверь в терминале команду `python3 --version` и перезапусти Unity (Unity
берёт PATH на момент старта).

## 9. Где лежат сохранения

Игра сохраняет прогресс в JSON-файл `cryptohack_save.json` в папке
`Application.persistentDataPath`:

| ОС | Путь |
|---|---|
| Windows | `C:\Users\<имя>\AppData\LocalLow\<компания>\<продукт>\` |
| Linux | `~/.config/unity3d/<компания>/<продукт>/` |
| macOS | `~/Library/Application Support/<компания>/<продукт>/` |

`<компания>` и `<продукт>` — из настроек проекта (*Edit → Project Settings →
Player*), у свежесозданных настроек это имя пользователя и имя проекта.
Скопируй файл, чтобы сделать бэкап; удали его (или нажми **⌁ GHOST → Сбросить
прогресс**) — игра начнётся с нуля. Также игра пишет рабочие файлы Python в
подпапку `py_run/` рядом с сохранением.

### Проверка кода без Unity

В репозитории есть скрипт-«линтер», который ловит опечатки в собственных классах
(несуществующие методы, неверное число аргументов, необъявленные поля) и ошибки
синтаксиса — удобно, если правишь код в текстовом редакторе:

```bash
pip install tree-sitter tree-sitter-c-sharp
python3 tools/check_cs.py Assets
```

(на системном Python с защитой PEP 668 может понадобиться
`pip install --break-system-packages …` или виртуальное окружение)

Ожидаемый вывод на чистом проекте — `ошибок синтаксиса 0, семантических
замечаний 0`. Этот скрипт использовался при разработке, потому что Unity в
сборочной среде не было; саму игру он не запускает.
